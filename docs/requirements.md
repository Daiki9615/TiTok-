# TikTok 動画文字起こしツール 要件定義書（ドラフト v0.1）

- 作成日: 2026-11-15 (JST)
- ステータス: ドラフト（「未決事項」の回答待ち）

---

## 1. 目的・背景

TikTok 動画の URL を入力するだけで、動画内の音声をテキスト化（文字起こし）して取得できるツールを作る。
動画を何度も見返さずに内容を確認・引用・要約・検索できるようにすることが狙い。

## 2. 想定ユーザー・利用シーン

| 項目 | 想定（仮） |
|---|---|
| 主な利用者 | 開発者本人（個人利用） |
| 利用シーン | 気になった動画の内容をメモしたい／競合・トレンド調査で話している内容を集めたい |
| 利用頻度 | 1日数本〜数十本 |

> ※ 利用者が「本人のみ」か「一般公開」かでアーキテクチャと法的リスクが大きく変わる（→ 未決事項 Q1）。

## 3. スコープ

### 3.1 対象（MVP）
- 公開されている TikTok 動画 1 本の URL を入力 → 文字起こしテキストを出力
- 短縮 URL（`vm.tiktok.com/...`, `vt.tiktok.com/...`）にも対応
- 日本語音声（自動言語判定で他言語も可）

### 3.2 対象外（MVP では扱わない）
- 非公開／友達限定／ログインが必要な動画
- LIVE 配信
- 複数 URL の一括処理、ユーザー単位の全動画取得（将来検討）
- 画面上のテロップ（字幕画像）の OCR（将来検討）
- 話者分離（誰が話したか）

## 4. 機能要件

| ID | 機能 | 内容 | 優先度 |
|---|---|---|---|
| F-01 | URL 入力 | TikTok URL を受け付け、形式を検証する。不正 URL はエラー表示 | 必須 |
| F-02 | 短縮 URL 解決 | `vm.` / `vt.` 短縮 URL をリダイレクト解決して正規 URL にする | 必須 |
| F-03 | 音声取得 | 動画（または音声のみ）を一時取得する | 必須 |
| F-04 | 既存字幕の優先利用 | 投稿に字幕（自動字幕含む）が付いていれば、まずそれを取得して返す（高速・低コスト） | 推奨 |
| F-05 | 音声認識 | 字幕が無い場合、音声認識（ASR）で文字起こしする | 必須 |
| F-06 | 結果表示 | 全文テキストを表示。ワンクリックでコピー | 必須 |
| F-07 | タイムスタンプ | 区間ごとの開始時刻付き表示（例 `[00:05] ...`） | 推奨 |
| F-08 | エクスポート | `.txt` / `.srt` / `.json` でダウンロード | 推奨 |
| F-09 | メタ情報表示 | 投稿者名・キャプション・動画の長さ | 任意 |
| F-10 | 進捗表示 | 取得中／文字起こし中などのステータス表示 | 推奨 |
| F-11 | 履歴 | 過去の文字起こし結果を一覧・再表示 | 任意（将来） |
| F-12 | 要約 | LLM による要約・要点抽出 | 任意（将来） |

### 処理フロー（MVP）

```
URL入力 → URL検証/短縮URL解決 → 字幕の有無を確認
   ├─ 字幕あり → 字幕を取得 → 整形 → 表示/エクスポート
   └─ 字幕なし → 音声を一時取得 → ASRで文字起こし → 整形 → 表示/エクスポート
                                   → 一時ファイル削除
```

## 5. 非機能要件

| 区分 | 要件（目標値・仮） |
|---|---|
| 性能 | 1分の動画を 60 秒以内に文字起こし完了（ASR 方式に依存。要検証） |
| 精度 | 日本語の一般的な話し言葉で実用レベル（数値目標は PoC で計測して決定） |
| 対応動画長 | 最大 10 分（TikTok の長尺動画を想定。上限は要確認） |
| データ保持 | 取得した動画/音声は処理後ただちに削除。テキストのみ保存（保存する場合） |
| セキュリティ | API キーは環境変数で管理しリポジトリに含めない |
| 保守性 | TikTok 側の仕様変更で取得処理が壊れやすいため、取得部分はモジュール分離し差し替え可能にする |
| コスト | 個人利用で月額数百円〜無料に収める（方式次第） |

## 6. 技術方針（案）

### 6.1 動画/音声・字幕の取得
- **yt-dlp** を利用（TikTok の動画・ユーザー・短縮 URL `vm.tiktok` に対応していると公式の対応サイト一覧に記載）
- 注意: TikTok 側の変更で動作しなくなることがある（一覧上でも一部 TikTok 抽出器は "Currently broken" 表記）。yt-dlp を定期的に更新する運用が必要

### 6.2 文字起こし（ASR）— 比較

| 方式 | 長所 | 短所 |
|---|---|---|
| A. OpenAI Whisper（ローカル, MIT ライセンス） | 無料・データが外部に出ない・日本語対応 | GPU が無いと遅い。マシン性能依存 |
| B. faster-whisper（Whisper の高速実装, ローカル） | A より高速・省メモリ | 同上（ただし CPU でも実用的になりやすい） |
| C. クラウド音声認識 API（OpenAI / Google / AWS 等） | 速い・環境構築が楽 | 従量課金・音声を外部送信 |

**推奨（MVP）: B. faster-whisper** — 無料・ローカル完結で個人利用に適する。速度不足なら C に切り替えられるよう ASR 部分をインターフェース化する。

### 6.3 アプリ形態 — 比較

| 形態 | 向いているケース |
|---|---|
| CLI（`python transcribe.py <URL>`） | 最速で作れる。本人のみ利用 |
| ローカル Web UI（Streamlit / Gradio 等） | ブラウザで URL を貼るだけにしたい。本人・少人数 |
| 公開 Web サービス（FastAPI + フロント + サーバー） | 不特定多数に提供。サーバー費用・法務対応が必要 |

**推奨: CLI で中核を作り → 同じロジックをローカル Web UI から呼ぶ**（段階的に拡張）。

### 6.4 想定構成（推奨案）

```
[ブラウザ UI (Streamlit)] or [CLI]
          │
   transcriber（中核ロジック, Python）
     ├─ fetcher : yt-dlp で字幕/音声取得（差し替え可能）
     ├─ asr     : faster-whisper（差し替え可能）
     └─ formatter : txt / srt / json 出力
```
- 言語: Python 3.11+
- 依存: yt-dlp, faster-whisper, ffmpeg

## 7. 法務・規約上の注意（重要）

- TikTok の利用規約は、プラットフォームが提供する機能以外の方法でのコンテンツ取得や自動化された手段でのアクセスを制限している可能性が高い。**推測ですが**、外部ツールでの動画ダウンロードは規約に抵触しうる。※本セッションでは tiktok.com にネットワーク上アクセスできず、規約原文を確認できていない（要確認）
- 文字起こしテキストは元動画の著作物の複製・翻案にあたりうる。私的利用の範囲を超えて公開・再配布・商用利用する場合は **専門家（弁護士）に確認が必要**
- 一般公開サービスにする場合は、規約順守・権利者からの削除要請対応・プライバシーポリシー整備が必要

## 8. 開発ステップ（案）

| フェーズ | 内容 | 完了条件 |
|---|---|---|
| 0. PoC | yt-dlp で取得 + faster-whisper で文字起こしできるか、数本で精度・速度を計測 | 日本語動画 5 本で結果を評価 |
| 1. MVP(CLI) | F-01〜F-08 を CLI で実装 | URL 1 つで txt/srt が出る |
| 2. Web UI | Streamlit で URL 入力画面 | ブラウザから利用可能 |
| 3. 拡張 | 履歴・一括処理・要約・OCR など | 必要に応じて |
