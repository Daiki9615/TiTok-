## 1. 目的

TikTok 動画の URL を入れると、音声を文字起こしして保存し、**集めた文字起こしをもとに、話されている内容の分析と傾向の把握ができる**ツールを作る。

## 2. 前提（確定事項）

| 項目 | 決定内容 |
|---|---|
| 利用者 | 本人のみ（公開しない） |
| 利用形態 | 自分の Mac 上で起動し、ブラウザで開く画面（ローカル Web UI） |
| 実行環境 | Mac |
| 文字起こし | Mac 上で無料で処理（クラウド API は使わない） |
| 対象言語 | 日本語のみ |
| 字幕の扱い | 投稿に字幕があっても使わず、**必ず音声から文字起こし**する |
| AI（LLM）機能 | 使わない（要約などはしない） |

## 3. スコープ

### 3.1 対象
- 公開されている TikTok 動画の URL（短縮 URL `vm.tiktok.com` / `vt.tiktok.com` を含む）
- 文字起こし結果と動画情報の保存（蓄積）
- 蓄積した文字起こしの分析・傾向表示（内容は 4.3 / 未決事項 Q8〜Q11 で確定）

### 3.2 対象外
- 非公開・友達限定・ログインが必要な動画、LIVE 配信
- LLM による要約・分類
- 画面上のテロップの読み取り（OCR）
- 話者の区別（誰が話したか）
- 日本語以外の言語

## 4. 機能要件

### 4.1 文字起こし

| ID | 機能 | 内容 | 優先度 |
|---|---|---|---|
| F-01 | URL 入力 | URL を貼り付けて実行。TikTok 以外や不正な URL はエラー表示 | 必須 |
| F-02 | 短縮 URL 解決 | 短縮 URL を元の URL に変換 | 必須 |
| F-03 | 音声取得 | 動画の音声を一時的に取得（処理後に削除） | 必須 |
| F-04 | 文字起こし | 音声認識で日本語テキストに変換（字幕の有無に関係なく常に実施） | 必須 |
| F-05 | 結果表示・コピー | 全文を表示し、ワンクリックでコピー | 必須 |
| F-06 | タイムスタンプ | 区切りごとに「何秒目の発言か」を表示 | 推奨 |
| F-07 | 書き出し | txt / srt / csv で保存 | 推奨 |
| F-08 | 進捗表示 | 「音声取得中」「文字起こし中」などを表示 | 推奨 |
| F-09 | 複数 URL 一括処理 | 複数の URL をまとめて貼り付けて順番に処理 | 推奨（分析用途のため） |

### 4.2 データ蓄積

| ID | 機能 | 内容 | 優先度 |
|---|---|---|---|
| D-01 | 保存 | 文字起こし結果を Mac 内のデータベース（SQLite）に保存 | 必須 |
| D-02 | 動画情報の保存 | 投稿者、投稿日、キャプション、ハッシュタグ、動画の長さ、再生数・いいね数（取得できる範囲） | 必須 |
| D-03 | 一覧・検索 | 保存済みの動画を一覧表示、キーワードで全文検索 | 必須 |
| D-04 | 重複防止 | 同じ動画を2回処理しない（再処理は手動で可能） | 推奨 |
| D-05 | タグ付け | 自分で分類ラベル（例: 競合A、美容系）を付ける | 推奨 |

※ 再生数・いいね数は「取得した時点」の値。後から変わる。

### 4.3 分析・傾向（案。Q8〜Q11 の回答で確定）

| ID | 機能 | 内容 | 優先度 |
|---|---|---|---|
| A-01 | 頻出語ランキング | よく話されている単語の上位を表示（「です」「ます」などの意味の薄い語は除外） | 必須 |
| A-02 | ワードクラウド | 頻出語を大きさで見せる図 | 推奨 |
| A-03 | 絞り込み | 期間・投稿者・タグ・ハッシュタグで対象を絞って分析 | 必須 |
| A-04 | 時系列の推移 | 特定の単語が出てくる回数を、投稿日ごとにグラフ表示 | 推奨 |
| A-05 | グループ比較 | 例: 投稿者A と B、タグ別で頻出語を並べて比較 | 推奨 |
| A-06 | 数値との関係 | 例: 特定の単語を含む動画と含まない動画で、平均再生数を比較 | 任意 |
| A-07 | 冒頭分析 | 最初の数秒で何を言っているか（つかみの言葉）の傾向 | 任意 |
| A-08 | 話す速さ | 1分あたりの文字数 | 任意 |
| A-09 | 書き出し | 分析結果を csv で保存 | 推奨 |

### 4.4 処理の流れ

```
URL入力（1件 or 複数）
 → URL確認・短縮URL変換
 → 動画情報と音声を取得（yt-dlp）
 → 音声を文字起こし（Mac上のWhisper）
 → 文字起こしと動画情報をDBに保存 → 一時音声ファイル削除
 → 画面で表示 / 書き出し
 → 分析画面で蓄積データを集計・グラフ表示
```

## 5. 非機能要件

| 区分 | 要件（目標値は仮。試作で測って決める） |
|---|---|
| 性能 | 1分の動画を 1 分以内に文字起こし（Apple シリコン Mac 想定） |
| 精度 | 日本語の話し言葉で実用レベル。試作で実際の動画を使って確認 |
| データ | すべて Mac 内に保存し、外部に送らない（TikTok からの取得を除く） |
| 起動 | ターミナルでコマンド1つで起動 → ブラウザで開く |
| 保守 | TikTok 側の変更で取得が壊れやすいため、取得部分を分けて作り、yt-dlp を定期更新する |
| 費用 | 無料（ソフトはすべて無料のもの） |

## 6. 技術方針（案）

| 役割 | 候補 | 理由 |
|---|---|---|
| 言語 | Python 3.11 以上 | 下記ライブラリがすべて Python で使える |
| 動画情報・音声の取得 | yt-dlp + ffmpeg | TikTok に対応 |
| 文字起こし | **mlx-whisper**（第一候補） | Apple の機械学習基盤 MLX（Apple シリコン向け）で Whisper を動かせる。Mac の GPU を使えるため速い見込み |
| 〃（代替） | whisper.cpp | Apple シリコンで Metal（GPU）による処理に対応。MIT ライセンス |
| 日本語の単語分割 | SudachiPy または Janome（PoC で比較） | 頻出語の集計には日本語の文を単語に分ける処理が必要 |
| 画面 | Streamlit | Python だけでブラウザ画面・グラフが作れる |
| 保存 | SQLite | Mac 内の1ファイルで完結 |
| グラフ | Streamlit 標準 / Plotly、ワードクラウドは wordcloud | |

※ v0.1 で推奨した faster-whisper は、Mac の GPU には対応しておらず（NVIDIA GPU と CPU のみ記載）、Mac では CPU 処理になるため第一候補から外した。

### 構成

```
[ブラウザ画面 (Streamlit)]
   ├─ 文字起こし画面 ─┐
   ├─ 一覧・検索画面  │
   └─ 分析画面        │
                       ▼
  core（Python）
   ├─ fetcher    : yt-dlp で情報・音声取得（差し替え可能）
   ├─ asr        : mlx-whisper（差し替え可能）
   ├─ storage    : SQLite
   ├─ analyzer   : 単語分割・集計
   └─ exporter   : txt / srt / csv
```

## 7. 規約・法律の注意

- TikTok の利用規約は未確認（作業環境から tiktok.com に接続できなかった）。推測ですが、外部ツールで動画を取得することは規約に反する可能性がある。本人だけの利用でもこのリスクはゼロではない
- 文字起こしテキストを公開・再配布・商用利用する場合は、著作権について専門家（弁護士）に確認が必要
- 大量の動画を短時間に取得すると、TikTok 側から制限される可能性がある（推測）。一括処理では間隔を空ける

## 8. 開発ステップ（案）

| 段階 | 内容 | 完了条件 |
|---|---|---|
| 0. 試作 | 実際の動画 5〜10 本で取得・文字起こしの精度と速度を測る。mlx-whisper のモデルサイズを決める | 精度・速度の結果表ができる |
| 1. 文字起こし画面 | F-01〜F-08、D-01〜D-02 | URL を貼ると結果が表示・保存される |

| 4. 追加 | A-06〜A-08 など | 必要に応じて |

## 用語

- **SRT**: 字幕ファイルの形式。各発言に「何秒から何秒か」を付けて並べたテキスト。動画編集ソフトや動画プレーヤーに読み込ませると字幕として表示できる。例:
  ```
  1
  00:00:00,000 --> 00:00:03,200
  今日は朝のルーティンを紹介します

  2
  00:00:03,200 --> 00:00:06,500
  まず起きたらすぐに水を飲みます
  ```
